## 2) เลือก C ด้วย inner validation (nested)

C และ temperature ถูกเลือกต่อ fold บน inner validation ที่กัน group แล้ว holdout ไม่มีส่วนในการเลือก
seed เปลี่ยนเฉพาะ inner split

| seed | mean LOSO macro-F1 | C ที่เลือก: ontoum224 / rf_robusta / rf_boos / agtron | macro-F1 ราย fold |
|---|---|---|---|
| 20261006 | 0.6056 | 0.1 / 0.0001 / 0.01 / 0.03 | 0.894 / 0.258 / 0.666 / 0.605 |
| 20261007 | 0.5461 | 0.1 / 0.0001 / 0.03 / 0.03 | 0.894 / 0.258 / 0.428 / 0.605 |
| 20261008 | 0.6056 | 0.1 / 0.0001 / 0.01 / 0.03 | 0.894 / 0.258 / 0.666 / 0.605 |
| **เฉลี่ย** | **0.5858 ± 0.0343** | | |

แย่กว่า B1 (0.6382) เพราะ **C ที่ดีบน inner validation ไม่ใช่ C ที่ดีกับ source ใหม่**
inner validation มาจาก source เดียวกับที่ใช้เทรน ตัวอย่างชัดที่สุดคือ fold rf_robusta:
inner validation ให้ C = 0.0001 ดีที่สุด (0.92) แต่บน holdout จริง C นั้นแย่ที่สุด (0.258 เทียบ 0.385 ที่ C = 0.01)

## สรุปตามกฎที่ประกาศไว้

| กฎ | ผล |
|---|---|
| หลัก: nested ต้องได้มากกว่า 0.6382 | ไม่ผ่าน (0.5858) |
| รอง: กฎ deploy เดิมบนตาราง sweep | เลือก C = 0.0003 (0.6504) |

การได้เพิ่ม 0.015 ใน sweep เป็นการเลือกค่าจาก holdout 4 fold โดยตรง (แบบเดียวกับที่เลือก C = 0.01 ตอนแรก)
จึงเป็นค่าที่ดูดีเกินจริง ส่วนวิธีเลือก C ที่ไม่พึ่ง holdout ที่ลองในรอบนี้ (inner validation) ให้ผลแย่กว่าการคง C = 0.01
ถ้าจะเปลี่ยน C ต้องยืนยันกับข้อมูลที่ไม่เคยใช้เลือก เช่น ภาพจากกล้องจริง หรือชุด test ที่แช่แข็ง (ซึ่งควรเปิดครั้งเดียว)

ถ้าต้องเลือกค่าไปทดสอบต่อ C = 0.003 เสียน้อยที่สุด: mean +0.015, pooled ไม่ลด, ผิดข้ามขั้นเพิ่มจาก 3.1% เป็น 4.2%
แต่การชี้ค่านี้ทำหลังเห็นตาราง จึงเป็นข้อเสนอสำหรับทดสอบ ไม่ใช่ข้อสรุป
